## THE REAL CAUSE: the ring, not the chart — and it is fixed

`/api/klines` serves the **in-memory 2,500-bar BarCache**, never the 21-day `bars` table. So
**493 MNQ 1m rows the store already held (2026-09-08 17:16 → 09-09 01:28 CT) were invisible to
the chart** — outcome **C2(a)**, the store was right and the display was wrong. That is a ring
problem wearing a chart's clothes, and it was fixed in the sibling wave **`fix/bars-horizon`**
(booted in the combined head **`8941ec68`**, 2026-09-10 06:57:24 CT), which made the ring
rehydrate 1m from the store on boot and made every history-bearing surface declare held-vs-requested.

**Section H tripped as well, and correctly.** The adjacent window 09-09 01:29 → 13:04 CT is a
**genuine 697-minute store hole** at 1m/3m/5m — outcome **C2(c)** — caused by the machine being
powered off (`who -b` → boot 13:01), not by any defect. A31 says a store hole is a different wave;
this one is not even a wave, it is an outage. The market traded through it (MNQ 15m carries
`v=150585` at the 08:30 CT RTH open), so those minutes are simply gone.

## WHAT THE READ FOUND THAT OUTLIVED THE WAVE

1. **`bars_integrity` cannot fail by construction.** It counts duplicate primary keys, which the
   table's UNIQUE index makes impossible. It printed `✅ bars integrity OK: dups=0 … total=91730`
   at 13:06:48 CT **while 697 consecutive minutes of MNQ 1m were missing**. A check that has never
   been capable of failing is decoration — the class-83 shape.
2. **The chart and the kernel share one horizon.** Both read `BarCache`, so a chart gap and a
   planner gap are the same population — which is what turned a display complaint into
   `fix/bars-horizon`.
3. **My own flat-gate query was wrong**, and it is recorded in class 99: `state IN ('armed','working')`
   is a hand-typed *positive* list that returned 0 while arm 143 rested at the broker in
   `place_pending`. A positive list fails OPEN; a negative list of terminal states fails SAFE. The
   code's own predicate is `isTerminalArmState` (`trader/one_contract.go:285-290`, seven states).

## A15 — WHAT THE OWNER WILL STILL SEE

The chart still reads the ring, not the store. `fix/bars-horizon` deepened what the ring *holds*
after a boot, so the horizon is longer and survives a restart — but a gap the ring never received
is still a gap the chart cannot draw. Serving the chart from the store is a separate, unclaimed
wave, and the honest statement is that this one did not do it.
