## Finding and implementation

[A] `trader/one_contract.go` had the full terminal predicate, but `armedActually` used a shorter terminal list, store readers used positive state lists, and the boot census added four named states. The boot sweep deliberately omitted cancel_pending; I initially misclassified that exclusion as a missing liveness reader. The 2026-09-10 correction below supersedes that conclusion. Leg 4 compared every non-terminal ledger row with the broker, including authorizations never sent. The earlier brand-visible observation (rows 133/134/135 versus broker snapshot 14449) demonstrated the resulting broker 1 / ledger 3 mismatch; the two extras were unplaced authorizations, not missing broker orders.

The original predicate moves to **store.IsTerminalArmState**, avoiding a store→trader import cycle. `store/arm_state.go` contains the sole classification table. `TerminalArmStateSQL()` is generated by applying that Go predicate to its known state names; the non-terminal fragment is its negation. Go and SQLite normalize casing and the same Unicode whitespace set. NULL/empty/unknown remain non-terminal, matching the original Go predicate rather than silently treating an unfamiliar row as finished.

Store live-row ordering, non-terminal selection, pre-boot selection, the boot census, one-contract logic, authored-arm logging and remaining arm readers now use the shared predicate. Lifecycle actions keep explicit single-state restrictions where appropriate. Unknown states therefore appear in liveness reads; UpsertArm conservatively refuses rewriting an unknown non-terminal row rather than treating it as a finished placement. A received rejection may settle a non-terminal row linked by its exact trader/signal; the update remains scoped and cannot resurrect terminal rows.

Leg 4 consumes the production ledger renderer through the additive `OpenOrder.arm_state` field (raw ledger state, independent of the display label), excludes terminal rows, and separates **armed + empty signal** into `armed_unplaced` plus a distinct informational detail line. Remaining rows count as working/unconfirmed. Pending placement is never downgraded to an authorization, including malformed rows missing identity. The broker book remains the comparison source. Two authorized arms with broker zero PASS; pending with broker zero FAIL; broker one with no ledger placement FAIL. The existing explicit pre-first-snapshot ledger fallback and broker freshness limit are unchanged by this task.

The existing record boot line now includes a separately read `arm placement census: N working/unconfirmed · M armed (authorized, no signal id; informational)`. Ledger failure prints UNKNOWN. API help, Guide and SYSTEM-MAP are updated in the implementation commit. GUIDE_BUILT_REV will be stamped from the clean built binary at an authorized deployment; this branch does not claim to be running.

## Every-reader boundary

`go run ./cmd/arm-state-sql` prints the canonical non-terminal SQL; `-terminal` prints its terminal form. The command opens no database. Python watches/audits can import `scripts/arm_state.py`, which evaluates the Go-derived SQL rather than owning a Python state list. The executable q51 audit and arm replay now use these sources. Captured JSON/CSV outputs and historical prose remain historical receipts; they are not silently re-generated or rewritten to claim new observations. The replay has synthetic `none`/`refused` states outside the ledger domain, handled explicitly around the shared arm predicate. Its old captured outcomes are not claimed revalidated here.

The source guard scans executable Go/Python/shell/SQL, JavaScript/TypeScript, PowerShell and C# wherever located, including report directories and untracked files. It rejects SQL state IN lists, literal SQL state sets, Go classification switches/boolean sets and OR-chained arm State comparisons. String-to-string display maps and plan-lifecycle fixtures are not arm classifiers. Reviewed broker-status readers are exempted by file and function; naming an arbitrary arm classifier argument `status` does not bypass the guard. NT8's broker-state classifier and the historical broker-order reaper replay are a different domain and are explicitly excluded; applying an arm-terminal predicate to broker states would itself be a bug. Like a grep test, this guard checks recognized source forms, not every possible obfuscation of arbitrary code.
