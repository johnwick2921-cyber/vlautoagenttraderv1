### Why the build lines say `match=NO`, and why that is expected

- **The comparison is exact string equality.** The live Go binary compares the AddOn's build id with its compiled-in constant that way (`AddonBuildLine`, `order_snapshot.go:216-230`, both revs).
- **So every build line from `0e490e44` reads `match=NO`.** m21 ≠ m2.
- **Two lines render it.**
  - The **🔌 line** prints once per trader per process, when that trader's class-33 boot sweep first completes. It printed at 00:46:33 CT, before the F5, and it never reprints after a reconnect or an F5.
  - The **🎯 stop-entry line** re-renders whenever its text changes, and it now shows m21.
- **The parenthetical is wrong for a newer build.** The `match=NO` text reads "NT8 is running an older DLL — recompile the AddOn (F5) and restart NT8". The function takes that branch for *any* unequal value (C3).
- **What a Go boot at `b16fef27` will show.** It should print `match=yes` on 🔌, but only if the AddOn's hello or heartbeat lands before the boot sweep completes.
  - Otherwise it prints `build_id=none … match=NO (no frame carrying a build_id received yet)`, which is not a failure; 3 of the 8 observed 🔌 emissions did this (`armed_executor.go:1773` comment).
  - A later rev that bumps `ExpectedAddonBuild` again reads `match=NO`.
  - Read the line; do not assume it (L7).
- **No behaviour depends on `ExpectedAddonBuild`.** In production it feeds only the two log renderers: `class33_boot_sweep.go:123` and `armed_executor.go:1778` at `0e490e44` (`:1786` at `b16fef27`) [A].

**The capability floors are satisfied.** `FarSideProven` is a bytewise `>=` on the whole string (`tcp_framing.go:336-341` at `0e490e44`, `:340-345` at `b16fef27`). `2026-09-23-m21` meets every floor, so moving from p1 to m21 opens and closes no Go capability gate [A]:

**What m21 changes with no hold present** [A, `git diff 3cc96e6f~1 b16fef27 -- ninjascript/`]. Three things:

1. The `build_id` reported on hello and heartbeat moves from p1 to m21. That meets every floor and changes only log text.

## Part A — the runbook

### Step 0 — preconditions (all of them, or stop)

1. **A flat window, checked before the compile.**

   - The route is a query parameter (`api/server.go:430-434` at `0e490e44`; the handler reads `c.Query("trader_id")`). `/api/traders/<id>/cutover-gate` is **not** a route and answers 404.
   - Without `trader_id` the handler falls back to the owner's **first** trader, so name each trader explicitly.
   - Token: run `go run ./cmd/gate-jwt <owner-email> data/data.db 2>/dev/null | grep -oE 'eyJ[A-Za-z0-9_.-]+' | tail -1` from the repo root `/home/hoang/nofx`. It reads `.env` from the cwd; anywhere else it signs with the default secret and the server answers 401.

### Step 1 — back up, copy, and verify the folder md5 == repo BEFORE F5

No F5 until the block prints `GATE: ALL FIVE MATCH`.

```bash
( set -uo pipefail
NT8="/mnt/c/Users/hoang/Documents/NinjaTrader 8"; A="$NT8/bin/Custom/AddOns"
REPO=/home/hoang/nofx        # any clone holding $SHA; git only READS its object store
SHA=b16fef27                 # the pinned commit
FILES="VLBarsSubscriptionManager VLContractResolver VLHistoryPull VLInstrumentLookup VLTraderTCPClient"
EMPTY=d41d8cd98f00b204e9800998ecf8427e   # md5 of empty input: never a MATCH

# 1a. the pinned commit has all five sources — checked BEFORE anything is written
[ -d "$A" ] || { echo "STOP: $A not found"; exit 1; }
for f in $FILES; do
  git -C "$REPO" cat-file -e "$SHA:ninjascript/$f.cs" || { echo "STOP: $f missing at $SHA in $REPO"; exit 1; }
done

# 1b. private backup of ALL FIVE sources NT8 has now (never the repo — it is public)
B=$HOME/nofx-backups/addon/$(date +%Y%m%d-%H%M%S)-pre-$SHA
install -d -m 700 "$B" || { echo "STOP: cannot create $B"; exit 1; }
for f in $FILES; do cp -p "$A/$f.cs" "$B/" || { echo "STOP: backup of $f failed"; exit 1; }; done
chmod 600 "$B"/*.cs && ( cd "$B" && md5sum *.cs > MD5SUMS ) && chmod 600 "$B/MD5SUMS" || { echo "STOP: backup incomplete"; exit 1; }
grep -n 'VL_BUILD_ID *=' "$B/VLTraderTCPClient.cs"      # the build a rollback returns to
echo "BACKUP DIR: $B"                                    # write it down — the Rollback needs it

# 1c. stage all five from git (a failed read never truncates a live file), then copy
S=$(mktemp -d) || exit 1
for f in $FILES; do
  git -C "$REPO" show "$SHA:ninjascript/$f.cs" > "$S/$f.cs" && [ -s "$S/$f.cs" ] || { echo "STOP: could not stage $f"; exit 1; }
done
for f in $FILES; do cp "$S/$f.cs" "$A/$f.cs" || { echo "STOP: copy of $f failed — go to Rollback"; exit 1; }; done
date '+COPIED AT %Y-%m-%d %H:%M:%S'                     # steps 3 and 4 read "after the copy"

# 1d. THE GATE: folder md5 == repo, every file; a failed read or an empty file is DIFF
bad=0
for f in $FILES; do
  r=$(git -C "$REPO" show "$SHA:ninjascript/$f.cs" | md5sum | cut -c1-32) || r=READ-FAILED
  l=$(md5sum < "$A/$f.cs" | cut -c1-32) || l=READ-FAILED
  if [ "$r" = "$l" ] && [ "$r" != "$EMPTY" ] && [ "$r" != READ-FAILED ]; then echo "$f MATCH $r"
  else echo "$f DIFF repo=$r live=$l"; bad=1; fi
done
[ "$bad" = 0 ] && echo "GATE: ALL FIVE MATCH — F5 allowed" || echo "GATE: DIFF — DO NOT PRESS F5 (Rollback restores $B)"
)
```

- **This gate exists because of tonight.** The two compiles at 01:28 built the **old** p1 source, because `VLTraderTCPClient.cs` had not been copied yet (B4).
- **Copy all five before touching the Editor.** Whether an open NinjaScript Editor auto-compiles when files change underneath it is unknown [C] (M1 §10). The block copies all five within one loop.
- **The block writes only to the NT8 folder and the backup dir.** `git cat-file` and `git show` read `$REPO`'s object store and write nothing to its tree.

### Step 4 — the wire proof: a hello on a NEW connection (the only proof)

The build is proven only by what the AddOn says on a new connection. These lines go to the **system journal only**; `data/nofx_*.log` holds logrus output and has none of them. Run the block below.

```bash
( journalctl -u nofx --since "<COPIED AT>" -o short-precise --no-pager \
    | grep -E 'tcp_server: (client connected|client disconnected|hello handshake OK)'
  /mnt/c/Windows/System32/tasklist.exe /FI "IMAGENAME eq NinjaTrader.exe" /FO CSV /NH | cut -d, -f1,2 )
```

**It passes when the LAST triple after the copy time is:**
1. `client disconnected`
2. `client connected addr=127.0.0.1:<port>`, on a port different from the previous connection's
3. `hello handshake OK protocol_version=3 source=vltrader-addon build_id=2026-09-23-m21 nt8_pid=<N> assembly_mvid=<32 hex>`

In the hello, `<N>` must equal the PID `tasklist` prints, and `<32 hex>` must differ from every earlier hello's.

**Which epoch fields you can actually see** [A]:
- `nt8_pid` and `assembly_mvid` appear only in that journal line.
- `nt8_start_ms`, `source_hash` and `activation_nonce` are recorded on the Go `ConnectionRecord` but printed nowhere: no log line, API view or boot line shows them (C4).
- `accept_seq` and `remote_port` appear in the `addon_ack` leg detail of `GET /api/installation-gate`, as `(accept_seq=N remote_port=P)`, behind JWT. `remote_port` equals the port in the `client connected` line.
- An AddOn older than m2 sends no epoch, and the line then prints `nt8_pid=0 assembly_mvid=""`. That zero means **not sent**, not PID 0 (C5).
