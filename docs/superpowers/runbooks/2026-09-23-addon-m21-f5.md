## Part A — the runbook

Paths are the WSL view. `NT8=/mnt/c/Users/hoang/Documents/NinjaTrader 8`. NT8 compiles ONLY from `$NT8/bin/Custom/AddOns/`, and editing the repo's `ninjascript/*.cs` alone does nothing.

### Step 0 — preconditions (all of them, or stop)

1. **A flat window.**
   - For every NT8 trader, `GET /api/cutover-gate?trader_id=<id>` returns `"ready": true`. That covers five legs: db_open_positions, api_positions, nt8_positions_snapshot, working_orders and planner_in_flight.
   - The token recipe is `go run ./cmd/gate-jwt <owner-email> data/data.db 2>/dev/null | grep -oE 'eyJ[A-Za-z0-9_.-]+' | tail -1`, run from the install dir. Capturing the whole stdout gives a malformed token.
   - The NT8 Control Center Positions and Orders tabs show nothing open or working on **any** account.
   - Why flat: every F5 is an in-process AddOn reload. The AddOn's TCP connection drops and reconnects, and the reload re-pulls history (M1 F3 (g): 44 `RequestBars` in 6 s). The flat check therefore runs **before** the compile, not only before a restart (M1 F3 (f)).
2. **Do not use `GET /api/installation-gate` as the flat check here.**
   - It is not READY by construction: with no hold there is no `maintenance_ack`, so `addon_ack` fails.
   - It also fails while any non-SIM connection is Connected (F1/Q1, R-k, R-r).
   - The F5 does not write a hold and does not change that gate.
3. **Pin the build.** The commit you copy from (below: `b16fef27`) must be on dev, and its `VL_BUILD_ID` must be the build you intend (`git show <sha>:ninjascript/VLTraderTCPClient.cs | grep -n 'VL_BUILD_ID *='`).
4. **Hash `Strategies\vltrader.cs` (R-m).**
   - It is compiled into the same assembly, has never been in git, and an error in it blocks every compile. It must be unchanged:
     `sha256sum "$NT8/bin/Custom/Strategies/vltrader.cs"` must equal the sha256 in `~/nofx-backups/addon/vltrader-cs-20260922/RECEIPT.txt` (`5c621520…304e`).
   - If it differs, stop and back it up first.

### Step 1 — back up, copy, and verify the folder md5 == repo BEFORE F5

No F5 until every file reads MATCH.

```bash
NT8="/mnt/c/Users/hoang/Documents/NinjaTrader 8"
SHA=b16fef27                               # the pinned commit
B=~/nofx-backups/addon/$(date +%Y%m%d-%H%M%S)-pre-$SHA
FILES="VLBarsSubscriptionManager VLContractResolver VLHistoryPull VLInstrumentLookup VLTraderTCPClient"

# 1a. private backup of ALL FIVE owned sources (never the repo — it is public)
install -d -m 700 "$B"
for f in $FILES; do cp -p "$NT8/bin/Custom/AddOns/$f.cs" "$B/"; done
chmod 600 "$B"/*.cs
( cd "$B" && md5sum *.cs > MD5SUMS && chmod 600 MD5SUMS )
grep -n 'VL_BUILD_ID *=' "$B/VLTraderTCPClient.cs"   # the build you can roll back to

# 1b. copy all five from the pinned commit (git show writes the blob bytes)
for f in $FILES; do
  git -C /home/hoang/nofx-101f5 show "$SHA:ninjascript/$f.cs" > "$NT8/bin/Custom/AddOns/$f.cs"
done
date '+copied at %H:%M:%S'                 # note this time; step 3 reads "after the copy"

# 1c. THE GATE: folder md5 == repo, every file
for f in $FILES; do
  r=$(git -C /home/hoang/nofx-101f5 show "$SHA:ninjascript/$f.cs" | md5sum | cut -c1-32)
  l=$(md5sum < "$NT8/bin/Custom/AddOns/$f.cs" | cut -c1-32)
  echo "$f repo=$r live=$l $([ "$r" = "$l" ] && echo MATCH || echo DIFF)"
done
```

- **Any `DIFF` → stop, and do not press F5.** Tonight's receipt (B4) is the reason this gate exists: the two compiles at 01:28 built the **old** p1 source, because `VLTraderTCPClient.cs` had not been copied yet.
- Copy all five before touching the Editor. Whether an open NinjaScript Editor auto-compiles when the files change underneath it is unknown [C] (M1 §10).
- Replace `/home/hoang/nofx-101f5` with any clone that has the pinned commit. `git show` reads the object database and writes nothing to that tree.

### Step 2 — F5, once, in the NinjaScript Editor

- Press F5 **only in the focused NinjaScript Editor window**. Only there is F5 `Compile`. In a Chart, Market Analyzer or SuperDOM window, F5 is `ReloadNinjaScript` (M1 F8, from NT8's own startup hotkey dump).
- **Press it once, then go to step 3.** Every compile is a full AddOn reload: connection drop, history re-pull. Tonight one intended F5 became six compiles (B4).
- Compile errors appear **only in the Editor's error grid**. NT8 writes nothing about compiles to its log or trace (M1 F5). An error in any file, including `Strategies\vltrader.cs`, blocks the whole assembly (M1 F10).
- If the grid shows errors: stop, do not restart NT8, and go to Rollback.

### Step 3 — prove the compile by its artifacts

NT8 logs nothing about compiles, so the proof is on disk and in the AddOn's own lines.

```bash
# 3a. the assembly was rewritten after the copy, and carries the new build string
ls -la --time-style=full-iso "$NT8"/bin/Custom/NinjaTrader.Custom.{dll,pdb,xml}
strings -el "$NT8/bin/Custom/NinjaTrader.Custom.dll" | grep -cx '2026-09-23-m21'   # ≥ 1

# 3b. the reload pair, after the copy time
grep -nE 'VLTraderTCPClient: (AddOn Terminated|AddOn Active|hello handshake OK)' \
  "$NT8/log/log.$(date +%Y%m%d).00000.en.txt" | tail -6
```

**3a passes when** the DLL mtime is later than the copy, the pdb and xml were written within about 250 ms of it (B3), and the new build string is present.

**3b passes when**, after the copy time, you see `AddOn Terminated`, then `AddOn Active, connecting to 127.0.0.1:36974` 10–31 ms later, then `hello handshake OK (protocol v3)`. Between them sit 8–9 other lines.

**Look-alikes that are NOT a reload:**
- `Terminated` with no `Active` after it is an NT8 **shutdown**.
- `Active` with no `Terminated` before it is a **new NT8 process**.
- A hello with no pair is a **Go** restart.

**A pair alone does not prove a compile.** Whether `ReloadNinjaScript` in a chart also cycles the AddOn is unknown [C]. The compile is proven by 3a plus a new `assembly_mvid` in step 4.

**Do NOT compare the hello's `assembly_mvid` with `bin/Custom/NinjaTrader.Custom.dll`.** It never matches.
- The hello reports the MVID of the per-compile assembly NT8 actually loaded, `$NT8/tmp/<guid>.dll`.
- The `bin/Custom` copy carries a different MVID.
- Tonight: `bin/Custom` = `8186ba3c…`, final hello = `c2299ac0…` = `tmp/d5b6b2d7….dll` [A]. See C2.

**If no pair appears within about 30 s:** the compile failed or F5 went to the wrong window. Read the Editor's error grid.

### Step 4 — the wire proof: a hello on a NEW connection (the only proof)

The build is proven only by what the AddOn says on a new connection. These lines go to the **system journal only**. `data/nofx_*.log` holds logrus output and has none of them.

```bash
journalctl -u nofx --since "<copy time>" -o short-precise --no-pager \
  | grep -E 'tcp_server: (client connected|client disconnected|hello handshake OK)'
/mnt/c/Windows/System32/tasklist.exe /FI "IMAGENAME eq NinjaTrader.exe" /FO CSV /NH | cut -d, -f1,2
```

**It passes when the LAST triple after the copy time is:**
1. `client disconnected`;
2. `client connected addr=127.0.0.1:<port>`, on a port different from the previous connection's;
3. `hello handshake OK protocol_version=3 source=vltrader-addon build_id=2026-09-23-m21 nt8_pid=<N> assembly_mvid=<32 hex>`.

Here `<N>` equals the PID `tasklist` prints, and `<32 hex>` differs from every earlier hello's.

**Which epoch fields you can actually see [A]:**
- Visible: `nt8_pid` and `assembly_mvid`. They appear only in that journal line.
- Recorded but printed nowhere: `nt8_start_ms`, `source_hash` and `activation_nonce` are kept on the Go `ConnectionRecord`, and no log line, API view or boot line shows them (C4).
- `accept_seq` and `remote_port` are visible in the `addon_ack` leg detail of `GET /api/installation-gate`, as `(accept_seq=N remote_port=P)` (JWT). `remote_port` equals the port in the `client connected` line.
- An AddOn older than m2 sends no epoch, and the line then prints `nt8_pid=0 assembly_mvid=""`. That zero means **not sent**, not PID 0 (C5).

**Capture these lines into the receipt the same night.** The system journal for `nofx` kept about 5 h tonight (earliest retained line 2026-09-22 20:52 CT).

### Step 5 — after the F5

- **The 🔌 boot line is not a receipt.** It prints once per process, at boot. On `0e490e44` it keeps saying what it said at 00:46:33, and the next Go boot at `b16fef27` or later prints `match=yes`.
- The 🎯 stop-entry line in `data/nofx_*.log` shows `addon build_id=2026-09-23-m21 expected=2026-09-22-m2 match=NO`. On `0e490e44` that is expected; see "State".
- **The feed is alive:**
  - `SELECT … FROM bars WHERE symbol='MNQ' AND tf='1m' AND source='live'` in `sqlite3 -readonly data/data.db` shows one row per minute with no gap.
  - NT8's watchdog lines read `dead-subscriptions=0`.
  - Live `bar_update` frames log at DEBUG, sampled (`tcp_server.go:1913-1917`), so the journal cannot show them.
- **The owner's F5 is the last step. No NT8 restart is required.** M1 F3 found that F5 hot-reloads the AddOn inside the running NT8, and tonight repeated it four times in PID 40804 (B6).
- **The owner may still restart.** If so:
  - login is manual (M1 F2);
  - a restart, unlike an in-process reload, disconnects **every** connection, including non-SIM ones (C7);
  - startup never compiles, so a restart **without** F5 keeps the old DLL.
  - After a restart, repeat step 4. The new hello carries the new `nt8_pid`.

### Rollback — restore the backed-up sources, F5, prove the OLD build on the wire

```bash
B=<the backup dir from step 1>
( cd "$B" && md5sum -c MD5SUMS )                     # the backup is intact
for f in $FILES; do cp "$B/$f.cs" "$NT8/bin/Custom/AddOns/$f.cs"; done
for f in $FILES; do                                  # folder == backup, every file
  [ "$(md5sum < "$B/$f.cs")" = "$(md5sum < "$NT8/bin/Custom/AddOns/$f.cs")" ] && echo "$f MATCH" || echo "$f DIFF"
done
```

Then do Step 2 (F5 in the Editor, once), Step 3 and Step 4, expecting the **old** build id.

- **Rolling back to p1**, tonight's prior build: the hello reads `build_id=2026-09-20-p1 nt8_pid=0 assembly_mvid=""`, because p1 sends no epoch fields.
  - With p1 there is **no** `assembly_mvid` to prove a fresh compile. The proof is the step-3 artifacts, plus a new `client connected` port carrying `build_id=2026-09-20-p1`.
- **There is no DLL to swap.** No p1 or m21 DLL backup exists; the newest DLL backup is `~/nofx-backups/nt8-addon/NinjaTrader.Custom.2026-09-05-g2.dll`. Rollback is source + F5 [A].
- **p1 still meets every Go floor**, because p1 is the picture-HTF floor itself and `>=` passes.
  - p1 has no `maintenance` handler. If a hold were ever written, no `maintenance_ack` would come back, `addon_ack` would fail, and the installation gate would stay not-READY: fail-closed [B, from the M2 gate code; not exercised with p1].
